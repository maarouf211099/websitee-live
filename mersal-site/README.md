# موقع مؤسسة مرسال الجديد

موقع ثابت (HTML/CSS/JS) + دالتين صغيرتين للدفع، يتنشر على **Azure Static Web Apps**.
مفيش سيرفر ولا داتابيز ولا DLLs — الكود كله هنا.

```
mersal-site/
  public/                الموقع (الصفحات، الصور، التصميم)
    index.html           الرئيسية
    donate.html          طرق التبرع + الدفع بالبطاقة (بنك مصر v100)
    zakat.html           حاسبة الزكاة
    about.html           عن مرسال
    contact.html         تواصل معنا
    volunteer.html       تطوع معنا (فورم)
    help.html            طلب مساعدة (فورم)
    community.html       مرسال كوميونيتي: هدايا المتبرعين (بتتفتح بعد أول تبرع)
    data/*.json          القائمة، بيانات الموقع، طرق التبرع، الهدايا، الألبومات… (بتتعدل من اللوحة)
    content.json         الحملات اللي في الرئيسية — عدّلها من هنا
    js/layout.js         الهيدر والفوتر وشريط الموبايل (بيانات التواصل بين علامتي mersal:site)
    staticwebapp.config.json  تحويل الروابط القديمة (/Donation ...) للصفحات الجديدة
  api/                   Azure Functions (Node 20)
    checkout             ينشئ جلسة دفع (نفس INITIATE_CHECKOUT الشغال حالياً)
    verify               يسأل البنك مباشرة؛ التبرع يتحسب بس لو CAPTURED، وبعدها يتبعت للسيستم الجديد
    forms                طلبات التطوع والمساعدة (+ تبويب الطلبات في اللوحة)
    admin / site         لوحة التحكم: الدخول، الحفظ على GitHub، بيانات الموقع
```

## الدفع بالبطاقة
الإعداد في أول `public/js/layout.js` ← `payMode`:
- `"demo"` (الحالي): كل خطوات التبرع شغالة (المبلغ والمشروع ← البيانات ← المراجعة) وبتقف عند بوابة بنك مصر برسالة إن الدفع قيد التفعيل وإن **مفيش أي مبلغ اتخصم**، وبتعرض طرق تانية للتبرع.
- `"live"`: دفع حقيقي، ومحتاج إعدادات بنك مصر تحت (`MPGS_MERCHANT` و`MPGS_API_PASSWORD` و`PUBLIC_BASE_URL`).
- `"off"`: يخفي الدفع بالبطاقة خالص.

أي زرار "تبرع الآن" جوا صفحة مشروع بيفتح التبرع ومحدد فيه المشروع ده (`/donate.html?for=p30`).

## النشر على Azure (مرة واحدة)
1. Azure Portal → **Create a resource → Static Web App**.
2. Plan: **Free** (فيه دومين مخصص وSSL مجاناً). Region: West Europe.
3. Source: **GitHub** → `maarouf211099/websitee-live` → الفرع.
4. Build presets: **Custom**
   - App location: `mersal-site/public`
   - Api location: `mersal-site/api`
   - Output location: *(فاضي)*
5. Create. Azure هيضيف GitHub Action للريبو وينشر تلقائياً مع كل push.

## الإعدادات (Static Web App → Settings → Environment variables)
| الاسم | القيمة |
|---|---|
| `MPGS_MERCHANT` | `TESTMERSAL` للتجربة، وبعدين `MERSAL` |
| `MPGS_API_PASSWORD` | باسورد الـAPI (الجديد بعد تغييره) |

## إرسال التبرعات للسيستم الجديد
بعد ما البنك يأكد الدفع، الموقع يبعت `POST` لـ `DONATION_WEBHOOK_URL`:
```json
{
  "source": "mersal-website",
  "orderId": "MERSAL-WEB-20261008120619-B5F51E",
  "amount": 250, "currency": "EGP", "purpose": "zakat",
  "donor": { "name": "...", "email": "...", "phone": "..." },
  "paidAt": "2026-10-08T10:00:00Z",
  "gatewayTransactionId": "1", "receipt": "R1"
}
```
- Header `X-Mersal-Signature: sha256=<HMAC-SHA256(body, DONATION_WEBHOOK_SECRET)>` للتأكد إن الطلب جاي من الموقع.
- **`orderId` مفتاح فريد**: ممكن نفس التبرع يتبعت أكتر من مرة (لو المتبرع عمل refresh)، فالسيستم لازم يتجاهل المكرر.
- `purpose`: `general | zakat | sadaqa | hospital | oncology | cases`.
- لو بنك مصر رفض بيانات المتبرع (`customer`)، الدفع بيكمل عادي بس `donor` هيوصل فاضي.

## لوحة التحكم (`/admin/`)
لوحة منفصلة على `https://<الموقع>/admin/`، الدخول باسم مستخدم وكلمة سر (مفيش حساب مايكروسوفت).
الـAPI بتاعها على `/api/console/*` (مش `/api/admin/*`: مسار `admin` محجوز في Azure Functions وبيرجّع 404).
كل حفظ من اللوحة = commit على فرع `main` في GitHub، والموقع بيتنشر تلقائياً خلال دقيقة تقريباً.

**اللي تقدر تعدّله من اللوحة:** السلايدر، حملات التبرع وأرقامها، "مرسال بالأرقام"، شريط المشاريع، كل صفحات المحتوى والصفحات الثابتة، القائمة، الألبومات والصور، بيانات التواصل والسوشيال والفوتر، الحسابات البنكية والمحافظ، هدايا الكوميونيتي، طلبات التطوع والمساعدة، وضع الدفع بالبطاقة، تقرير التبرعات، وكلمة سر اللوحة.

### أول دخول
- اسم المستخدم: `admin` (أو قيمة `ADMIN_USER` في Azure).
- أول مرة اللوحة هتطلب **كود التفعيل** الموجود في `api/setup.json` وهتختار كلمة السر بنفسك؛ بتتحفظ كـ hash في `public/data/settings.json` والكود بيبطل بعدها.
- تقدر تغيّر كلمة السر من تبويب الإعدادات ← حساب الأدمن. ولو عايز تثبّتها من Azure ظبّط `ADMIN_PASSWORD` (و`ADMIN_SECRET` اختياري لتوقيع الجلسة).
- الجلسة كوكي آمنة لمدة 12 ساعة، و5 محاولات غلط بتقفل الدخول 10 دقايق.

### الإعداد (مرة واحدة)
1. **صلاحية الحفظ:** GitHub → Settings → Developer settings → Fine-grained tokens → token على ريبو `websitee-live` بصلاحية **Contents: Read and write** بس.
   ثم في Static Web App → Settings → **Environment variables**:

   | الاسم | القيمة |
   |---|---|
   | `GITHUB_TOKEN` | التوكن (مطلوب للحفظ وللدخول) |
   | `GITHUB_REPO` | `maarouf211099/websitee-live` |
   | `GITHUB_BRANCH` | `main` |
2. **تقرير التبرعات (اختياري):** Storage Account وConnection string في `DONATIONS_STORAGE`.

لو الحفظ طالع "غير متصل" في تبويب الإعدادات → راجع الخطوة 1.

## الصفحة الرئيسية (السلايدر)
- السلايدر مش بيتبني في المتصفح: `api/src/lib/hero.js` بيكتبه جاهز جوه `public/index.html` بين علامات `<!-- mersal:hero -->` عشان أول صورة تظهر فوراً من غير فلاش.
- لوحة التحكم بتعمل ده لوحدها لما تحفظ "الرئيسية". لو عدّلت `content.json` يدوياً شغّل: `node tools/render-home.js`.
- كل شريحة: `banner` (1920×570، الصورة شمال والنص يمين)، وعلى الموبايل بيظهر جزء الصورة بس فوق والنص تحته في الكارت (`mobile` = قصّة الشمال 46%، بتتعمل تلقائياً) مع `kicker` / `title` / `text` / `button` / `link` / `focus`.
  لو الصورة الأصلية صغيرة وطلعت مش واضحة على الموبايل، ارفع من اللوحة "صورة الموبايل" (صورة مستقلة بعرض 900px أو أكتر) وهي اللي هتظهر في الكارت.

## السرعة والصور
- `tools/optimize_images.py` بيضغط كل الصور في `public/img` (JPEG بجودة 76 وبحد أقصى 1600px، وصور السلايدر 1920px بجودة 80) وبيعمل نسخة `.webp` جنب كل صورة وقصّة الموبايل لكل شريحة.
  شغّله بعد ما تضيف صور يدوياً في `public/img` (الصور اللي بتترفع من لوحة التحكم مش محتاجاه).
- الصور في الكروت والسلايدر بتتعرض عبر `mersalPic()` في `js/layout.js` (WebP + تحميل مؤجل).
- الكاش: الصور 30 يوم (أسماء ثابتة)، أما CSS/JS والصفحات 30 ثانية بس عشان أي نشر يظهر فوراً (في `staticwebapp.config.json`).

## المحتوى المنقول من الموقع القديم
`tools/import_old_site.py` بيقرا الموقع القديم (القايمة، كل صفحات الـCMS، السلايدر، طرق التبرع، الأرقام، المشاريع)
ويكتب `public/p/<id>.html` و`public/img/old/` و`public/data/menu.json` و`public/content.json`.
الروابط القديمة `/DynamicPage/RenderPage?id=N` بتتحول تلقائياً لـ `/p/N.html`.
بعد ما الموقع القديم يتقفل، عدّل الصفحات دي مباشرة.

## تعديل المحتوى (يدوي من الكود)
الأسهل من لوحة التحكم فوق. لو عايز تعدّل من الكود:
- الحملات: `public/content.json` (عنوان، نص، صورة، رابط، واختياري `goal`/`raised` لشريط التقدم).
- الحسابات البنكية والمحافظ: `public/data/donate.json`.
- التليفونات والعنوان والسوشيال: الكائن `SITE` بين `/* mersal:site */` و`/* /mersal:site */` في `public/js/layout.js` (ونسخة في `public/data/site.json`).
- القائمة: `public/data/menu.json`. هدايا الكوميونيتي: `public/data/community.json`.

## الصفحات الداخلية والألبومات و404 (التلميع)
### الصفحات الداخلية `public/p/*.html`
- القالب في `tools/import_old_site.py` ← `page_html(title, body, desc, cover, share_img, pid, crumbs=None)`:
  - `crumbs` اختياري: قائمة `[(عنوان الأب, رابطه أو None), ...]` تُكتب كمسار صفحة ثابت داخل `.page-head` (بدون قفزة تحميل).
    لو مش موجود، `js/legacy.js` بيبنيه من `data/menu.json` زي الأول.
  - صورة الغلاف ما بتتكررش: لو `cover` هي نفسها صورة البانر (`share_img`) ما بتتحطش تاني جوه المحتوى.
  - كل صفحة فيها `canonical` و`og:image` (الافتراضي `/img/hero.jpg` للصفحات اللي ملهاش صورة) و`twitter:card`.
  - المحتوى جوه `<article class="legacy">` (كان `div`).
- **لإعادة توليد الصفحات بعد أي تغيير في القالب** (من غير ما تنزّل الموقع القديم تاني):
  اقرأ كل `p/<id>.html`، خد العنوان والوصف و`og:image` وغلاف `.legacy-cover` والجسم بين `<!-- mersal:content -->` و`<!-- /mersal:content -->`،
  واحسب الـcrumbs من `data/menu.json`، ثم اكتب `page_html(...)`. (`python3 -I tools/regen_pages.py`.)
- `js/legacy.js` بيعمل تلقائياً عند التحميل:
  - تنظيف: يشيل العناوين/الفقرات الفاضية (`&nbsp;`)، يحوّل زرار "Submit Donation Online" القديم لرابط تبرع، يصلّح روابط الصور اللي كانت بتودّي لملفات الموقع القديم (`/ClientFilesLayout/...`)، ويلف الجداول في `.table-scroll` (تتزحلق أفقياً على الموبايل).
  - الصور: أي `carousel` قديم (Bootstrap 3) أو صف فيه 3 صور أو أكتر بيتحول لشريط صور بالسحب (`.gallery` + نقط + عدّاد + أسهم على الديسكتوب). ما فيش تدوير تلقائي بقى.
  - الأسئلة الشائعة: الأكورديون بيتفتح بأنيميشن (grid-rows) مع `aria-controls`، والرابط `#collapseN` بيفتح السؤال مباشرة.
  - شريط المشاركة: أيقونات (واتساب، فيسبوك، إكس، نسخ الرابط، و"مشاركة…" لو المتصفح بيدعم `navigator.share`). على الموبايل أيقونات دائرية 44px.
  - "صفحات ذات صلة": كروت بنفس شكل كروت الرئيسية، وعلى الموبايل شريط أفقي بالسحب.
- `css/legacy.css`: المقاس المقروء للفقرات (74ch)، `h1` داخل المحتوى بخط سفلي ذهبي، `h2`/`h4` شرائط، `h3` بحد جانبي ذهبي، `hr` فاصل متدرج، القوائم المتداخلة بنقط صغيرة، الصور اللي ليها `style="height:..."` من الـCMS القديم بتتظبط تلقائياً، إطار الخرائط/يوتيوب يتمدد بنسبة ثابتة.
- مسار الصفحة على الموبايل سطر واحد: العنوان الطويل بينقص بـ`…`.
- كارت التبرع الجانبي (ديسكتوب) `position: sticky` داخل `.page-grid` فمش ممكن يركب على الفوتر (اتقاس: 1366px، أطول صفحة).

### الألبومات `public/albums.html`
- على الموبايل عمودين بصور مربعة وعدد الصور على الصورة؛ أول صورتين بيتحملوا فوراً والباقي `lazy`.
- اللايت بوكس: سحب بالإصبع (الصورة بتمشي مع الإصبع)، أسهم الكيبورد (← التالية في RTL)، Home/End، Esc، عدّاد `1 / 10`، تحميل مسبق للصورة اللي بعدها واللي قبلها، زرار الرجوع في المتصفح بيقفله، والرابط `?a=N` بيفتح ألبوم معين.

### التبرع / تواصل / الزكاة / 404 (CSS فقط - `css/site.css`)
- التبرع على الموبايل: التبويبات كلها ظاهرة كأزرار (صفين) والمختار مميّز بعلامة ✓؛ أزرار المبالغ 48px؛ مؤشر الخطوات رقم + اسم + خط وصل؛ الصور الجانبية كارتين جنب بعض (وعلى التابلت 2 عمود في نص الصفحة)؛ صورة حساب ألمانيا ما بتطلعش بره الشاشة.
- تواصل معنا: كل بيان كارت بأيقونة (تليفون/إيميل/واتساب/عنوان/دعم فني) من غير تغيير في HTML (`:has()` + أيقونات SVG داخل CSS). كارت واتساب الفاضي مخفي فعلاً (قاعدة `[hidden]` عامة).
- الزكاة: الخانات أكبر (46px، خط 17px)، على الموبايل كل خانة تحت عنوانها، وكارت النتيجة بيفضل ثابت أعلى الشاشة وأنت بتكتب (مضغوط: الرقم + زرار + التفاصيل في سطرين).
- 404: صفحة ودودة - رقم 404 بقلب، عرض الرابط اللي ما اتلقاش، خانة بحث بتفتح بحث الهيدر (`js/layout.js`) وتنقل الكلمة، 8 روابط سريعة بأيقونات، وأزرار التبرع والاتصال. روابط الموقع القديم اللي فيها `?id=N` بتتحول لـ`/legacy.html?id=N`.

### عام (`css/site.css`)
- حلقة تركيز موحدة لكل العناصر (`:focus-visible`: ذهبي + حلقة داكنة فتبان على الأبيض وعلى الأخضر).
- حالة الضغط على اللمس لكل الأزرار والرقائق (تصغير بسيط من غير hover عالق).
- `prefers-reduced-motion`: كل الأنيميشن والانتقالات بتتوقف (قاعدة عامة في آخر الملف)، ما عدا حلقات التحميل.
- طباعة: صفحتي التبرع والزكاة بتتطبع من غير هيدر/فوتر/شريط سفلي، وكل طرق التبرع (بنك/محافظ/مندوب/خارج مصر) ظاهرة في ورقة واحدة.
- اتشالت قواعد CSS مش مستخدمة في أي HTML/JS (اتأكدنا بـgrep): `.hero*`، `.grid-4`، `.stats/.stat/.stats-title`، `.qd-head/.qd-row/.qd-purpose/.qd-amount`، `.unit-price`، `.goal-box/.goal-top/.goal-bottom`، `.camp-actions`، `#ways`.
  أعمدة Bootstrap في `legacy.css` (`col-md-*`, `col-lg-*`, `text-center`) اتسابت عمداً لأن محتوى الصفحات بيتعدل من لوحة التحكم وممكن يرجع يستخدمها.
- ملاحظة: `canonical` و`og:image` بيستخدموا `SITE_URL` من `tools/import_old_site.py` (حالياً رابط azurestaticapps). بعد ربط الدومين: `SITE_URL=https://www.mersal-ngo.org` وأعد توليد الصفحات.

## مرسال كوميونيتي (`/community.html`)
صفحة هدايا المتبرعين. بتتفتح بس على الجهاز اللي اتبرع من الموقع (التبرعات بتتسجل في `localStorage` عند الوصول لبوابة البنك أو عند تأكيد الدفع)، وساعتها بيظهر عنصر **"هداياك"** في شريط الموبايل تحت وسطر في قائمة الموبايل.
- شهادة شكر باسم المتبرع ومبلغه (صورة بتتعمل في المتصفح، تحميل أو مشاركة)، كارت "ابعت فرحة" للمشاركة، متابعة الحملة اللي دعمها، جروب واتساب (لما يتحط رابطه)، تطوع، تبرع شهري.
- شارات: أول تبرع، متبرع دائم (3 تبرعات)، متبرع شهري، داعم ذهبي (5000 جنيه).
- التعديل من اللوحة ← تبويب **الكوميونيتي** (`public/data/community.json`).

## لوحة التحكم: بيانات الموقع، القائمة، المشاريع، طرق التبرع، الصفحات الثابتة

كل حاجة كانت مكتوبة يدوياً في الكود بقت تتعدّل من اللوحة. زي باقي اللوحة: كل حفظ = commit على GitHub والموقع بيتنشر خلال دقيقة.

### تبويب "بيانات الموقع"
- **التواصل:** الخط الساخن، الهاتف، واتساب (اختياري)، البريد، العنوان. بتظهر في الهيدر والفوتر وصفحة تواصل معنا وزرار "اتصل" في شريط الموبايل.
  لو كتبت رقم واتساب بيظهر كرابط `wa.me` في الفوتر وكارت في صفحة تواصل معنا (الرقم المصري `01xxxxxxxxx` بيتحول تلقائياً لـ `+20`).
- **السوشيال:** فيسبوك، إنستجرام، إكس، لينكدإن، يوتيوب، تيك توك. الخانة الفاضية = الأيقونة مش بتظهر.
- **الفوتر:** اسم المؤسسة والنبذة اللي تحت الشعار (وسطر الحقوق).
- **طرق التبرع:** الحسابات البنكية (اسم، عملة، رقم، IBAN/SWIFT اختياري)، أرقام المحافظ/إنستاباي، وبيانات التبرع من خارج مصر (صورة حساب GLS + رابط).
- وضع الدفع بالبطاقة (`payMode`) فضل في تبويب الإعدادات زي ما هو.

**فين البيانات؟**
- التواصل/السوشيال/الفوتر: جوه `public/js/layout.js` بين العلامتين `/* mersal:site */ … /* /mersal:site */` (الكائن `SITE`) عشان الصفحات متعملش طلب إضافي، ونسخة في `public/data/site.json` لأي أداة تانية.
  الـAPI (`api/src/functions/site.js` → `GET/PUT /api/console/site`) بيعيد كتابة الكتلة دي بالكامل بعد التحقق من القيم، فلو عدّلتها يدوياً خلّيها كائن عادي (مفتاح: قيمة في كل سطر، من غير تعليقات جواها). `payMode` بيفضل جوه نفس الكائن وبيتغير من endpoint الإعدادات بس.
- طرق التبرع: `public/data/donate.json` (`banks`, `wallets`, `foreign`) → `PUT /api/console/data/donate`. صفحة `donate.html` بتقراه عند التحميل (`js/donate.js`)، والـHTML اللي فيها هو النسخة الاحتياطية لو الملف فشل.
- أي صفحة تقدر تعرض بيانات الموقع بـ `data-site="hotline|phone|whatsapp|email|address"` (النص والرابط بيتملوا من `SITE`)، وعنصر `data-site-box` بيتخفي لو القيمة فاضية.

### تبويب "القائمة"
محرر `public/data/menu.json`: عناصر رئيسية (رابط مباشر أو مجموعة) وتحت كل عنصر روابط فرعية. إضافة/حذف/إعادة تسمية/ترتيب ▲▼، واختيار الصفحة من قائمة (صفحات الموقع + كل صفحات المحتوى) أو كتابة رابط حر.
الروابط اللي كانت بتتضاف يدوياً في `layout.js` (اتصل بنا، الألبومات، تبرع الآن، حساب الزكاة) بقت جوه `menu.json`، واتضاف تحت "ساعد مرسال": **تطوع معنا** (`/volunteer.html`) و**طلب مساعدة** (`/help.html`)، و"طلب مساعدة" كمان في روابط الفوتر.

### الرئيسية: مشاريع مرسال
قسم في تبويب الرئيسية لشريط المشاريع (`content.json` → `projects`): اسم، وصف، صورة (900/600)، صفحة المشروع، ونص الزرار (اختياري). نفس أزرار الحملات (رفع صورة، ▲▼، حذف).

### الصفحات الثابتة
في تبويب الصفحات القائمة بتبدأ بعنوان **"صفحات ثابتة"**: عن مرسال، تواصل معنا، كارت عافية، حاسبة الزكاة (`public/<id>.html`)، وبعدها "صفحات المحتوى" (`public/p/<id>.html`).
الجزء القابل للتعديل في كل صفحة ثابتة محاط بـ `<!-- mersal:content --> … <!-- /mersal:content -->` (عن مرسال: كل المحتوى، تواصل معنا: المقدمة وكروت التواصل من غير الفورم، كارت عافية وحاسبة الزكاة: نص المقدمة).
نفس الـendpoint `GET/PUT /api/console/page/{id}`؛ الـid لازم يكون رقم أو واحد من القائمة الثابتة دي، والصفحات الثابتة مش بتتسجل في `pages.json`.

## الطلبات: تطوع معنا وطلب مساعدة (`/volunteer.html` و`/help.html`)
صفحتان عامتان، كل واحدة فيها فورم، وتبويب **الطلبات** في لوحة التحكم لمتابعتها.

- **تطوع معنا** `/volunteer.html`: الاسم، الموبايل، السن، البريد (اختياري)، المدينة/المنطقة، طرق المساعدة (مستشفى / قوافل / تصميم وسوشيال / جمع تبرعات / أخرى)، الوقت المناسب، رسالة.
- **طلب مساعدة** `/help.html`: اسم المريض، نوع الحالة (علاج شهري / عملية / أورام / أطفال / أخرى)، المستشفى أو التشخيص، وصف الحالة، مقدم الطلب وصلة القرابة، الموبايل ورقم بديل، المحافظة والمدينة، دخل الأسرة الشهري (اختياري)، موافقة على استخدام البيانات.
- التحقق في المتصفح وعلى السيرفر: رقم موبايل مصري `01xxxxxxxxx` (بيقبل `+20` والأرقام العربية ويحوّلها)، أطوال قصوى، تنظيف النصوص.
- حماية من البوتات: خانة مخفية (honeypot) + وقت التعبئة (أقل من 3 ثواني = بوت)، و**5 طلبات لكل IP في الساعة** (`FORMS_RATE_LIMIT`). البوت بيشوف شاشة "نجاح" ومفيش حاجة بتتحفظ.
- بعد الإرسال: شاشة نجاح برقم طلب (`MV-YYYYMMDD-XXXXX` للتطوع، `MH-...` للمساعدة)، زرار واتساب على رقم الموقع (`whatsapp` أو `phone` في بيانات الموقع) برقم الطلب جاهز، واتصال بالخط الساخن 19340.

### فين بتتحفظ الطلبات (بالترتيب)
1. **Azure Table** اسمه `requests` في نفس الـStorage Account بتاع `DONATIONS_STORAGE` (partitionKey = النوع، rowKey = رقم الطلب). الأفضل: مفيش commits وبيستحمل أي عدد.
2. لو `DONATIONS_STORAGE` مش موجود (أو الجدول وقع): **ملفات في GitHub** `api/data/requests/<id>.json` + فهرس `api/data/requests/index.json` (commit لكل طلب على فرع النشر؛ مجلد `api/` مش بيتنشر على الموقع). الفهرس بيحتفظ بآخر 2000 طلب، والباقي موجود كملفات.
3. اختياري وبالإضافة للي فوق: `FORMS_WEBHOOK_URL` بيستقبل `POST` بكل طلب جديد (نفس شكل تبرعات `DONATION_WEBHOOK_URL`):
   - Header `X-Mersal-Event: request.volunteer` أو `request.help`.
   - Header `X-Mersal-Signature: sha256=<HMAC-SHA256(body, FORMS_WEBHOOK_SECRET)>` (لو `FORMS_WEBHOOK_SECRET` فاضي بيستخدم `DONATION_WEBHOOK_SECRET`).
   - الـbody: `{ source: "mersal-website", event, id, type, createdAt, status, name, phone, altPhone, email, city, gov, summary, data: {...كل الخانات} }`. `id` مفتاح فريد.

لو مفيش ولا واحد من التلاتة، الفورم بيرجع 503 وبيطلب من الزائر يتصل بـ 19340، وتبويب الطلبات في اللوحة بيكتب الإعداد الناقص.

### الـAPI (`api/src/functions/forms.js`)
| | |
|---|---|
| `POST /api/forms/volunteer` و`POST /api/forms/help` | عام. يرجّع `{ ok, ref }`. أخطاء: 400 `{ message, errors: { field: msg } }`، 429 (الحد الأقصى)، 503 (مفيش تخزين). |
| `GET /api/console/requests?type=&status=&from=&to=` | أدمن. `{ enabled: { table, github, webhook }, store: "table" \| "github" \| null, rows }` (الأحدث الأول). |
| `GET /api/console/requests/{id}` | أدمن. الطلب كامل بالتفاصيل (صفوف فهرس GitHub بتيجي من غير `data`، التبويب بيجيبها عند الضغط على "تفاصيل"). |
| `PATCH /api/console/requests/{id}` body `{ status: new \| contacted \| done \| rejected }` أو `{ note }` | أدمن. Merge في الجدول أو إعادة كتابة الملف والفهرس في GitHub. |

### تبويب الطلبات في اللوحة (`public/admin/tabs/requests.js`)
