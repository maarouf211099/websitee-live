# موقع مؤسسة مرسال الجديد

موقع ثابت (HTML/CSS/JS) + دالتين صغيرتين للدفع، يتنشر على **Azure Static Web Apps**.
مفيش سيرفر ولا داتابيز ولا DLLs — الكود كله هنا.

```
mersal-site/
  public/                الموقع (الصفحات، الصور، التصميم)
    index.html           الرئيسية
    donate.html          طرق التبرع + الدفع بالبطاقة (بنك مصر v100)
    zakat.html           حاسبة الزكاة
    gift.html            إهداء التبرع (كارت إهداء) + تذكير شهري
    about.html           قديمة: بتتحول لـ /p/3.html (عن مرسال)
    contact.html         تواصل معنا (فورم رسالة)
    volunteer.html       تطوع معنا (فورم)
    help.html            طلب مساعدة (فورم)
    community.html       مرسال كوميونيتي: هدايا المتبرعين (بتتفتح بعد أول تبرع مدفوع)
    privacy.html         سياسة الخصوصية
    terms.html           شروط الاستخدام
    offline.html         الصفحة اللي بتظهر من غير نت (sw.js)
    sw.js                الـservice worker (العمل من غير نت)، وjs/pwa.js بيسجّله
    manifest.json        بيانات التطبيق لما يتثبت على الموبايل
    seo/                 نسخة JSON-LD بتاعة المؤسسة (اللي جوه index.html)
    fonts/               خطوط Cairo وTitillium Web (OFL) بدل Google Fonts
    data/*.json          القائمة، بيانات الموقع، طرق التبرع، الهدايا، الألبومات… (بتتعدل من اللوحة)
    content.json         الحملات اللي في الرئيسية — عدّلها من هنا
    js/layout.js         الهيدر والفوتر وشريط الموبايل (بيانات التواصل بين علامتي mersal:site)
    staticwebapp.config.json  تحويل الروابط القديمة (/Donation ...) للصفحات الجديدة + الكاش والـheaders
  api/                   Azure Functions (Node 20)
    checkout             ينشئ جلسة دفع (نفس INITIATE_CHECKOUT الشغال حالياً)
    verify               يسأل البنك مباشرة؛ التبرع يتحسب بس لو CAPTURED، وبعدها يتبعت للسيستم الجديد
    forms                طلبات التطوع والمساعدة وتسجيل التبرعات والمندوب (+ تبويب الطلبات في اللوحة)
    admin / site         لوحة التحكم: الدخول، الحفظ على GitHub، بيانات الموقع
```

## الدفع بالبطاقة
الإعداد في أول `public/js/layout.js` ← `payMode`:
- `"demo"` (الحالي): كل خطوات التبرع شغالة (المبلغ والمشروع ← البيانات ← المراجعة) وبتقف عند بوابة بنك مصر برسالة إن الدفع قيد التفعيل وإن **مفيش أي مبلغ اتخصم**، وبتعرض طرق تانية للتبرع.
- `"live"`: دفع حقيقي، ومحتاج إعدادات بنك مصر تحت (`MPGS_MERCHANT` و`MPGS_API_PASSWORD` و`PUBLIC_BASE_URL`).
- `"off"`: يخفي الدفع بالبطاقة خالص.

السيرفر نفسه بيمشي على نفس المفتاح: `/api/checkout` بيرفض (403) أي جلسة دفع لو الوضع مش `"live"` (بيقرا `payMode` من `layout.js` على GitHub كل دقيقة)، ولو حطيت `PAY_MODE` في إعدادات Azure هو اللي بيتحكم واللوحة مش هتقبل وضع مخالف له.
وكمان فيه حد: `CHECKOUT_RATE_LIMIT` (10) جلسات لكل IP في الساعة و`CHECKOUT_GLOBAL_LIMIT` (300) في الساعة للكل، عشان محدش يستخدم حساب التاجر لتجربة كروت مسروقة.
كل جلسة دفع بتتسجل كـ "عملية معلقة" في جدول `orders` (لو `DONATIONS_STORAGE` موجود)، ولو المتبرع دفع وقفل الصفحة قبل ما يرجع للموقع، زرار **"مراجعة العمليات المعلقة"** في تبويب التبرعات بيسأل البنك عن أي عملية عدّى عليها 15 دقيقة ويسجّل المدفوع ويبعته للـwebhook (مرة واحدة بس لكل `orderId`). لو بنك مصر فعّل إشعارات الـwebhook عندهم: ظبّط `MPGS_NOTIFICATION_SECRET` وخليهم يبعتوا على `POST /api/mpgs/notify` بالـheader `X-Notification-Secret`؛ العملية بتتقري من البنك نفسه مش من الطلب.

أي زرار "تبرع الآن" جوا صفحة مشروع بيفتح التبرع ومحدد فيه المشروع ده (`/donate.html?for=p30`).

## النشر على Azure (مرة واحدة)
1. Azure Portal → **Create a resource → Static Web App**.
2. Plan: **Free** (فيه دومين مخصص وSSL مجاناً). Region: West Europe.
3. Source: **GitHub** → `maarouf211099/websitee-live` → الفرع.
4. Build presets: **Custom**
   - App location: `mersal-site/public`
   - Api location: `mersal-site/api`
   - Output location: *(فاضي)*
5. Create. Azure هيضيف GitHub Action للريبو وينشر تلقائياً مع كل push.

## الإعدادات (Static Web App → Settings → Environment variables)
| الاسم | القيمة |
|---|---|
| `MPGS_MERCHANT` | `TESTMERSAL` للتجربة، وبعدين `MERSAL` |
| `MPGS_API_PASSWORD` | باسورد الـAPI (الجديد بعد تغييره) |
| `DONATION_WEBHOOK_URL` | رابط السيستم الجديد اللي يستقبل التبرعات (اختياري لحد ما يجهز) |
| `DONATION_WEBHOOK_SECRET` | سر مشترك لتوقيع الطلب (اختياري) |
| `PUBLIC_BASE_URL` | `https://www.mersal-ngo.org` بعد ربط الدومين |

اختياري: `MPGS_GATEWAY`، `MERCHANT_DISPLAY_NAME` (افتراضي MERSAL CHARITY)، `MIN_AMOUNT` (10)، `MAX_AMOUNT`، `ORDER_PREFIX` (MERSAL-WEB)، `PAY_MODE` (يثبّت وضع الدفع للسيرفر)، `CHECKOUT_RATE_LIMIT` / `CHECKOUT_GLOBAL_LIMIT`، `MPGS_NOTIFICATION_SECRET`، `CLIENT_IP_HEADER` (اسم header تاني للـIP لو المنصة اتغيرت؛ الافتراضي `X-Azure-ClientIP` / `X-Client-IP` وبعدها آخر عنوان عام في `X-Forwarded-For`).

## الدومين
Static Web App → **Custom domains** → `www.mersal-ngo.org` (CNAME) و`mersal-ngo.org`.
غيّر الـDNS بس بعد ما تجرب تبرع حقيقي على رابط `*.azurestaticapps.net`.

## إرسال التبرعات للسيستم الجديد
بعد ما البنك يأكد الدفع، الموقع يبعت `POST` لـ `DONATION_WEBHOOK_URL`:
```json
{
  "source": "mersal-website",
  "orderId": "MERSAL-WEB-20261008120619-B5F51E",
  "amount": 250, "currency": "EGP", "purpose": "zakat",
  "donor": { "name": "...", "email": "...", "phone": "..." },
  "paidAt": "2026-10-08T10:00:00Z",
  "gatewayTransactionId": "1", "receipt": "R1"
}
```
- Header `X-Mersal-Signature: sha256=<HMAC-SHA256(body, DONATION_WEBHOOK_SECRET)>` للتأكد إن الطلب جاي من الموقع.
- **`orderId` مفتاح فريد**: الموقع بيعلّم التبرع إنه اتبعت (في جدول `donations`) ومش بيبعته تاني، بس لو التخزين مش متظبط أو الـwebhook ما ردش ممكن يوصل أكتر من مرة، فالسيستم لازم يتجاهل المكرر.
- `purpose`: `general | zakat | sadaqa | hospital | oncology | cases`.
- لو بنك مصر رفض بيانات المتبرع (`customer`)، الدفع بيكمل عادي بس `donor` هيوصل فاضي.

## لوحة التحكم (`/admin/`)
لوحة منفصلة على `https://<الموقع>/admin/`، الدخول باسم مستخدم وكلمة سر (مفيش حساب مايكروسوفت).
الـAPI بتاعها على `/api/console/*` (مش `/api/admin/*`: مسار `admin` محجوز في Azure Functions وبيرجّع 404).
كل حفظ من اللوحة = commit على فرع `main` في GitHub، والموقع بيتنشر تلقائياً خلال دقيقة تقريباً.
لو اتنين أدمن (أو تابين) بيعدّلوا نفس الملف، الحفظ التاني بيترفض برسالة "حد تاني عدّل الملف ده" بدل ما يمسح تعديل الأول (كل `GET` بيرجّع نسخة الملف في `X-Mersal-Sha` واللوحة بتبعتها مع الحفظ في `X-Mersal-Base`). الحفظ بيرفض كمان أي بيانات ناقصة أو روابط مش آمنة (`javascript:` أو `//host`؛ المسموح `/…` و`#` و`https://` و`tel:` و`mailto:`).

**اللي تقدر تعدّله من اللوحة:** السلايدر، حملات التبرع وأرقامها، "مرسال بالأرقام"، شريط المشاريع، كل صفحات المحتوى والصفحات الثابتة، القائمة، الألبومات والصور، بيانات التواصل والسوشيال والفوتر، الحسابات البنكية والمحافظ، هدايا الكوميونيتي، الأخبار، أثر التبرع، شريط الإعلان وشريط «بتتبرع من خلال»، طلبات التطوع والمساعدة والتبرعات المسجّلة والمندوب، وضع الدفع بالبطاقة، تقرير التبرعات، وكلمة سر اللوحة.

### أول دخول
- اسم المستخدم: `admin` (أو قيمة `ADMIN_USER` في Azure).
- أول مرة اللوحة هتطلب **كود التفعيل** = **آخر 8 حروف من `GITHUB_TOKEN`** اللي حطيته في Azure (أو قيمة `ADMIN_SETUP_CODE` لو ظبطتها)، وهتختار كلمة السر بنفسك.
  الريبو عام، فمفيش أي سر محفوظ فيه: كلمة السر بتتحفظ في `public/data/settings.json` كـ hash متشفّر بسر من التوكن، ولو غيّرت التوكن اللوحة بترجع لأول دخول بكود التوكن الجديد.
- تقدر تغيّر كلمة السر من تبويب الإعدادات ← حساب الأدمن. ولو عايز تثبّتها من Azure ظبّط `ADMIN_PASSWORD` (و`ADMIN_SECRET` اختياري لتوقيع الجلسة).
- الجلسة كوكي آمنة لمدة 4 ساعات بتتجدد طول ما اللوحة مفتوحة، وبحد أقصى 12 ساعة من الدخول. تغيير كلمة السر بيخرّج كل الأجهزة التانية، وفي زرار **"تسجيل الخروج من كل الأجهزة"** في الإعدادات.
- 5 محاولات غلط بتقفل الدخول 10 دقايق، وكمان `ADMIN_LOGIN_LIMIT` (20) محاولة غلط لكل IP في الساعة و`ADMIN_LOGIN_GLOBAL_LIMIT` (200) للكل (العدادات دي بتتشارك بين كل نسخ السيرفر لما `DONATIONS_STORAGE` يكون موجود). نفس الحد على تأكيد كلمة السر الحالية عند تغييرها.

### الإعداد (مرة واحدة)

   ثم في Static Web App → Settings → **Environment variables**:

لو الحفظ طالع "غير متصل" في تبويب الإعدادات → راجع الخطوة 1.

## الصفحة الرئيسية (السلايدر)
- السلايدر مش بيتبني في المتصفح: `api/src/lib/hero.js` بيكتبه جاهز جوه `public/index.html` بين علامات `<!-- mersal:hero -->` عشان أول صورة تظهر فوراً من غير فلاش.
- لوحة التحكم بتعمل ده لوحدها لما تحفظ "الرئيسية". لو عدّلت `content.json` يدوياً شغّل: `node tools/render-home.js`.
- كل شريحة: `banner` (1920×570، الصورة شمال والنص يمين) مع `kicker` / `title` / `text` / `button` / `link` / `focus`.
- على الموبايل الكارت "ستوري" طولي: قصّة الصورة (الشمال 46% من البانر) بتملا حوالي 80% من الكارت والنص فوق تدرّج في آخرها، و`focus` بيحدد الجزء اللي يفضل ظاهر من القصّة (مثلاً `35% 50%`).
  عشان تبان حادة على شاشات الموبايل (3x): `tools/optimize_images.py` بيعمل القصّة بحجمين مكبّرين بفلتر Lanczos + unsharp: `<banner>-m.jpg` (2x = 1766×1140) و`<banner>-ms.jpg` (1.5x = 1324×855، للموبايلات dpr 2) وكل واحدة ليها `.webp`.
  `tools/render-home.js` بيقرا عرض الملفين وبيكتبهم `srcset` + `sizes="140vw"` (الصورة بتتعرض أعرض من الشاشة لأنها بتتقص بالطول في كارت طولي) وبيحط نفس الـsrcset في `<link rel=preload>` عشان أول صورة تتحمّل بدري.
  ملحوظة: الحفظ من اللوحة بيبني السلايدر من غير `-ms` (نسخة الـ2x بس)؛ شغّل `node tools/render-home.js` بعدها لو عايز ترجّع نسخة الـ1.5x.
- لما ترفع بانر جديد من اللوحة، اللوحة بتعمل `-m` لوحدها بعرض 1800px. ولو عايز صورة موبايل مستقلة ("صورة الموبايل" في اللوحة) ارفع صورة عرضها 1800px أو أكتر (أفضل طولية 4:5)؛ اللوحة مش بتكبّرها، فالصغيرة هتفضل صغيرة.

## السرعة والصور
- `tools/optimize_images.py` بيضغط كل الصور في `public/img` (JPEG بجودة 76 وبحد أقصى 1600px، وصور السلايدر 1920px بجودة 80) وبيعمل نسخة `.webp` جنب كل صورة وقصّتي الموبايل (`-m` و`-ms`) لكل شريحة.
  شغّله بعد ما تضيف صور يدوياً في `public/img` (الصور اللي بتترفع من لوحة التحكم مش محتاجاه).
- الصور في الكروت والسلايدر بتتعرض عبر `mersalPic()` في `js/layout.js` (WebP + تحميل مؤجل).
- الكاش: الصور 30 يوم (أسماء ثابتة)، أما CSS/JS والصفحات 30 ثانية بس عشان أي نشر يظهر فوراً (في `staticwebapp.config.json`). الـservice worker مش بيغيّر ده: CSS/JS دايماً من النت (شوف "التطبيق والعمل من غير نت").
- الخطوط (Cairo وTitillium Web) محفوظة في `public/fonts/` ومتحمّلة مسبقاً (`<link rel="preload">`)، وبتتكاش سنة. صفحات الموقع مش بتطلب Google Fonts (اللوحة بس).

## المحتوى المنقول من الموقع القديم
`tools/import_old_site.py` بيقرا الموقع القديم (القايمة، كل صفحات الـCMS، السلايدر، طرق التبرع، الأرقام، المشاريع)
ويكتب `public/p/<id>.html` و`public/img/old/` و`public/data/menu.json` و`public/content.json`.
الروابط القديمة `/DynamicPage/RenderPage?id=N` بتتحول تلقائياً لـ `/p/N.html`.
بعد ما الموقع القديم يتقفل، عدّل الصفحات دي مباشرة.

## تعديل المحتوى (يدوي من الكود)
الأسهل من لوحة التحكم فوق. لو عايز تعدّل من الكود:
- الحملات: `public/content.json` (عنوان، نص، صورة، رابط، واختياري `goal`/`raised` لشريط التقدم).
- الحسابات البنكية والمحافظ: `public/data/donate.json`. كل حساب بنكي عنصر في `banks` (`name`، `currency`، `number`، `iban`/`swift` اختياري، `logo` اختياري)، والحسابات اللي ورا بعض بنفس `name` بتظهر في كارت واحد للبنك بشعاره (الشعارات في `public/img/banks/` ومعاها `.webp`؛ من غير شعار بيظهر أول حرف من اسم البنك). نفس الكروت مكتوبة في `donate.html` جوه `#bank-accounts` كنسخة احتياطية، فلو غيّرت الحسابات من الكود حدّثها هناك كمان.
- التليفونات والعنوان والسوشيال: الكائن `SITE` بين `/* mersal:site */` و`/* /mersal:site */` في `public/js/layout.js` (ونسخة في `public/data/site.json`).
- القائمة: `public/data/menu.json`. هدايا الكوميونيتي: `public/data/community.json`.

## الصفحات الداخلية والألبومات و404 (التلميع)
### الصفحات الداخلية `public/p/*.html`
- القالب في `tools/import_old_site.py` ← `page_html(title, body, desc, cover, share_img, pid, crumbs=None)`:
  - `crumbs` اختياري: قائمة `[(عنوان الأب, رابطه أو None), ...]` تُكتب كمسار صفحة ثابت داخل `.page-head` (بدون قفزة تحميل).
    لو مش موجود، `js/legacy.js` بيبنيه من `data/menu.json` زي الأول.
  - صورة الغلاف ما بتتكررش: لو `cover` هي نفسها صورة البانر (`share_img`) ما بتتحطش تاني جوه المحتوى.
  - كل صفحة فيها `canonical` و`og:image` (الافتراضي `/img/hero.jpg` للصفحات اللي ملهاش صورة) و`twitter:card`.
  - المحتوى جوه `<article class="legacy">` (كان `div`).
- **لإعادة توليد الصفحات بعد أي تغيير في القالب** (من غير ما تنزّل الموقع القديم تاني):
  اقرأ كل `p/<id>.html`، خد العنوان والوصف و`og:image` وغلاف `.legacy-cover` والجسم بين `<!-- mersal:content -->` و`<!-- /mersal:content -->`،
  واحسب الـcrumbs من `data/menu.json`، ثم اكتب `page_html(...)`. (`python3 -I tools/regen_pages.py`.)
- `js/legacy.js` بيعمل تلقائياً عند التحميل:
  - تنظيف: يشيل العناوين/الفقرات الفاضية (`&nbsp;`)، يحوّل زرار "Submit Donation Online" القديم لرابط تبرع، يصلّح روابط الصور اللي كانت بتودّي لملفات الموقع القديم (`/ClientFilesLayout/...`)، ويلف الجداول في `.table-scroll` (تتزحلق أفقياً على الموبايل).
  - الصور: أي `carousel` قديم (Bootstrap 3) أو صف فيه 3 صور أو أكتر بيتحول لشريط صور بالسحب (`.gallery` + نقط + عدّاد + أسهم على الديسكتوب). ما فيش تدوير تلقائي بقى.
  - الأسئلة الشائعة: الأكورديون بيتفتح بأنيميشن (grid-rows) مع `aria-controls`، والرابط `#collapseN` بيفتح السؤال مباشرة.

## الحركة والانتقالات

كل الحركة في الموقع `transform` / `opacity` بس (وخط الـSVG في أيقونة النسخ وعلامة الصح)، عشان تفضل 60 إطار في الثانية على الموبايل، وبتتقفل كلها تلقائياً لو الجهاز مفعّل "تقليل الحركة" (آخر بلوك في `css/site.css`؛ أي keyframes جديدة تتضاف هناك).

- **الانتقال بين الصفحات**: View Transitions API في `css/site.css` (`@view-transition { navigation: auto }`): الصفحة القديمة بتطلع لفوق وتختفي والجديدة بتطلع من تحت (~220ms). الهيدر (`header`) والشريط السفلي (`m-bar`) ومؤشره (`m-ind`) ليهم `view-transition-name` فبيفضلوا ثابتين، والمؤشر بينزلق من العنصر القديم للجديد. المتصفحات اللي مش بتدعم بتعمل انتقال عادي.
- **الشريط السفلي والقائمة** (`js/layout.js`): مؤشر نشط بينزلق تحت العنصر (`.m-ind` بـ `--i`)، نبضة حمرا على "هداياك"، قائمة الموبايل بتفتح وتقفل بحركة (`.closing`) وصفوفها بتدخل ورا بعض، والأقسام بتتفتح بأنيميشن ارتفاع (`grid-template-rows` + `.is-open`).
- **الظهور عند التمرير**: `window.mersalReveal(els)` بيراقب العناصر من 48px قبل ما تدخل الشاشة ويظهرها مرة واحدة؛ اللي بيدخلوا في نفس الإطار بيتأخروا 70ms ورا بعض. من غير JavaScript مفيش حاجة بتتخفي.
- **التبرع** (`js/donate.js`): الخطوات بتنزلق (`data-dir`)، خط التقدم بيتملي، شريط ملخص لاصق فوق الخطوة 2 و3 (`.s-sum`) مع زر "تعديل"، وزر النسخ بتتحول أيقونته لعلامة صح (`.copy.done`).
- **الزكاة** (`zakat.html`): الإجمالي بيعد لحد الرقم الجديد وبيعمل نبضة. **الفورم** (`css/forms.css`): هزة خفيفة على الحقول الغلط عند الإرسال، وعلامة الصح بترسم نفسها في شاشة النجاح. **الصفحات الداخلية** (`css/legacy.css`): الأسئلة الشائعة أنعم، شريط المشاركة بيدخل زرار زرار، وشريط الصور بيتسحب بالماوس مع اندفاع. **الألبومات**: الصورة بتتكبر عند الفتح وتتصغر عند القفل. **الكوميونيتي**: الشارات بتظهر بنبضة والأرقام بتلف زي عداد الرئيسية والشهادة بتتكبر.

## لوحة التحكم: بيانات الموقع، القائمة، المشاريع، طرق التبرع، الصفحات الثابتة

كل حاجة كانت مكتوبة يدوياً في الكود بقت تتعدّل من اللوحة. زي باقي اللوحة: كل حفظ = commit على GitHub والموقع بيتنشر خلال دقيقة.

### تبويب "بيانات الموقع"
- **التواصل:** الخط الساخن، الهاتف، واتساب (اختياري)، البريد، العنوان. بتظهر في الهيدر والفوتر وصفحة تواصل معنا وزرار "اتصل" في شريط الموبايل.
  لو كتبت رقم واتساب بيظهر كرابط `wa.me` في الفوتر وكارت في صفحة تواصل معنا (الرقم المصري `01xxxxxxxxx` بيتحول تلقائياً لـ `+20`).
- **السوشيال:** فيسبوك، إنستجرام، إكس، لينكدإن، يوتيوب، تيك توك. الخانة الفاضية = الأيقونة مش بتظهر.
- **الفوتر:** اسم المؤسسة والنبذة اللي تحت الشعار (وسطر الحقوق).
- **طرق التبرع:** الحسابات البنكية (اسم، عملة، رقم، IBAN/SWIFT اختياري)، أرقام المحافظ/إنستاباي، وبيانات التبرع من خارج مصر (البنك، اسم صاحب الحساب، IBAN بيتحفظ من غير مسافات، BIC/SWIFT، صورة حساب GLS + رابط).
- وضع الدفع بالبطاقة (`payMode`) فضل في تبويب الإعدادات زي ما هو.

**فين البيانات؟**
- التواصل/السوشيال/الفوتر: جوه `public/js/layout.js` بين العلامتين `/* mersal:site */ … /* /mersal:site */` (الكائن `SITE`) عشان الصفحات متعملش طلب إضافي، ونسخة في `public/data/site.json` لأي أداة تانية.
  الـAPI (`api/src/functions/site.js` → `GET/PUT /api/console/site`) بيعيد كتابة الكتلة دي بالكامل بعد التحقق من القيم، فلو عدّلتها يدوياً خلّيها كائن عادي (مفتاح: قيمة في كل سطر، من غير تعليقات جواها). `payMode` بيفضل جوه نفس الكائن وبيتغير من endpoint الإعدادات بس.
- طرق التبرع: `public/data/donate.json` (`banks`, `wallets`, `foreign`) → `PUT /api/console/data/donate`. صفحة `donate.html` بتقراه عند التحميل (`js/donate.js`)، والـHTML اللي فيها هو النسخة الاحتياطية لو الملف فشل.
- أي صفحة تقدر تعرض بيانات الموقع بـ `data-site="hotline|phone|whatsapp|email|address"` (النص والرابط بيتملوا من `SITE`)، وعنصر `data-site-box` بيتخفي لو القيمة فاضية.

### تبويب "القائمة"
محرر `public/data/menu.json`: عناصر رئيسية (رابط مباشر أو مجموعة) وتحت كل عنصر روابط فرعية. إضافة/حذف/إعادة تسمية/ترتيب ▲▼، واختيار الصفحة من قائمة (صفحات الموقع + كل صفحات المحتوى) أو كتابة رابط حر.
الروابط اللي كانت بتتضاف يدوياً في `layout.js` (اتصل بنا، الألبومات، تبرع الآن، حساب الزكاة) بقت جوه `menu.json`، واتضاف تحت "ساعد مرسال": **تطوع معنا** (`/volunteer.html`) و**طلب مساعدة** (`/help.html`)، و"طلب مساعدة" كمان في روابط الفوتر.

### الرئيسية: مشاريع مرسال
قسم في تبويب الرئيسية لشريط المشاريع (`content.json` → `projects`): اسم، وصف، صورة (900/600)، صفحة المشروع، ونص الزرار (اختياري). نفس أزرار الحملات (رفع صورة، ▲▼، حذف).

### الصفحات الثابتة
في تبويب الصفحات القائمة بتبدأ بعنوان **"صفحات ثابتة"**: تواصل معنا، كارت عافية، حاسبة الزكاة (`public/<id>.html`)، وبعدها "صفحات المحتوى" (`public/p/<id>.html`). "عن مرسال" هي صفحة المحتوى `/p/3.html` (اللي الزوار بيشوفوها)، و`about.html` القديمة مش بتتعدل من اللوحة.
الجزء القابل للتعديل في كل صفحة ثابتة محاط بـ `<!-- mersal:content --> … <!-- /mersal:content -->` (تواصل معنا: المقدمة وكروت التواصل من غير الفورم، كارت عافية وحاسبة الزكاة: نص المقدمة).
نفس الـendpoint `GET/PUT /api/console/page/{id}`؛ الـid لازم يكون رقم أو واحد من القائمة الثابتة دي، والصفحات الثابتة مش بتتسجل في `pages.json`.

في `admin/admin.css` سطر `[hidden] { display: none !important; }` لأن `.login` و`.shell` و`.field` عندهم `display` صريح؛ أي عنصر جديد في اللوحة بيستخدم `hidden` بيشتغل زي المتوقع.

- الاسم والموبايل والبريد اللي فورم البطاقة حفظهم على الجهاز (`mersalDonor`) بيتملوا تلقائياً في الفورمين، و`?for=hospital` أو `?for=p30` بيختار الغرض.

- بعد الإرسال: شاشة نجاح برقم طلب (`MV-YYYYMMDD-XXXXX` للتطوع، `MH-...` للمساعدة، `MT-...` للتبرع المسجّل، `MP-...` للمندوب)، زرار واتساب على رقم الموقع (`whatsapp` أو `phone` في بيانات الموقع) برقم الطلب جاهز، واتصال بالخط الساخن 19340.
- `js/forms.js` بيشغّل كل `<form data-form="...">` في الصفحة؛ كل فورم بيلاقي صندوق الخطأ وشاشة النجاح بتوعه من `data-alert` / `data-success` (الافتراضي `#form-alert` / `#form-success`)، وأي صندوق عليه `data-show-if="method=bank"` بيظهر ويتراجع ويتبعت بس لما الخانة دي تبقى بالقيمة دي.

### فين بتتحفظ الطلبات
1. **Azure Table** اسمه `requests` في نفس الـStorage Account بتاع `DONATIONS_STORAGE` (partitionKey = النوع، rowKey = رقم الطلب). ده المكان الوحيد: الريبو على GitHub **عام**، فبيانات المرضى والتليفونات والعناوين عمرها ما بتتكتب فيه.
2. اختياري وبالإضافة للجدول: `FORMS_WEBHOOK_URL` بيستقبل `POST` بكل طلب جديد (نفس شكل تبرعات `DONATION_WEBHOOK_URL`):
   - Header `X-Mersal-Event: request.volunteer` أو `request.help` أو `request.contact` أو `request.transfer` أو `request.pickup`.
   - Header `X-Mersal-Signature: sha256=<HMAC-SHA256(body, FORMS_WEBHOOK_SECRET)>` (لو `FORMS_WEBHOOK_SECRET` فاضي بيستخدم `DONATION_WEBHOOK_SECRET`).
   - الـbody: `{ source: "mersal-website", event, id, type, createdAt, status, name, phone, altPhone, email, city, gov, summary, meta?, data: {...كل الخانات} }`. `id` مفتاح فريد.
   - `meta` (للتبرع المسجّل والمندوب بس) فيه الخانات اللي القائمة والـCSV محتاجينها: التبرع المسجّل `{ amount, currency, method, bank, date, purpose, caseCode }`، المندوب `{ kind, amount, currency, purpose, area, date, slot }`. بيتحفظ كعمود `meta` في الجدول. في المندوب `gov` = المحافظة و`city` = المنطقة.

لو الجدول مش متظبط (أو وقع) والـwebhook ما استلمش، الفورم بيرجع 503 وبيطلب من الزائر يتصل بـ 19340، وتبويب الطلبات في اللوحة بيعرض تنبيه أحمر: "ضيف DONATIONS_STORAGE (Azure Table) - الطلبات مش بتتحفظ".

### الـAPI (`api/src/functions/forms.js`)
| | |
|---|---|

### تبويب الطلبات في اللوحة (`public/admin/tabs/requests.js`)
فلاتر (النوع: تطوع / طلب مساعدة / رسالة / تبرع مسجّل / مندوب، الحالة، من - إلى، بتوقيت القاهرة)، عدّادات لكل حالة (وعدد "جديد" على زرار التبويب)، جدول (التاريخ، النوع، الاسم، الموبايل كرابط اتصال، المكان، ملخص، الحالة، ملاحظة، تفاصيل)، تصدير CSV. تغيير الحالة أو الملاحظة بيتحفظ فوراً من غير زرار حفظ.
- **تبرع مسجّل**: الملخص بيبين المبلغ والعملة، الطريقة والبنك، تاريخ التحويل، الغرض وكود الحالة. **مندوب**: فلوس + المبلغ أو التبرع العيني، يوم ووقت التحصيل، والمكان = المحافظة - المنطقة. التفاصيل فيها كل الخانات (رقم العملية، العنوان، الملاحظات...).
- الـCSV (والـCSV بتاع التبرعات): أي خانة بتبدأ بـ `=` أو `+` أو `-` أو `@` بيتحط قبلها `'` عشان Excel وSheets ميشغلوهاش كمعادلة (النصوص جاية من فورمات عامة).
- الـCSV فيه أعمدة زيادة (فاضية للتطوع والمساعدة): المبلغ (رقم من غير فواصل عشان يتجمع)، العملة، طريقة التبرع، البنك، نوع التبرع، الغرض، كود الحالة، تاريخ التحويل / التحصيل، وقت التحصيل.
- الحالات نفسها للكل: "جديد" ← "تم التواصل" (أكدنا التحويل / رتبنا الميعاد) ← "تم" (التبرع اتأكد واتخصص / المندوب استلم) أو "مرفوض".

## أثر التبرع (`تبرعك بيعمل إيه`)
حاسبة بتعرض للزائر تبرعه بيغطي إيه بالظبط: مبلغ (كتابة / أزرار مقترحة / شريط سحب) وتحته كروت بتتحدث فوراً بعداد متحرك: "3 جرعات في علاج مرضى الأورام"، "سهمين في كفالات مرضى"، ولو المبلغ أقل من الوحدة بيظهر نسبة مئوية وشريط (مثلاً 100 جنيه = 50% من سهم كشف وتحاليل). الزرار الرئيسي **تبرع بـ N جنيه** بيروح لـ `/donate.html?amount=N#online`، وكل كارت ليه رابط حملته (`?for=p31&amount=N`). على صفحة التبرع نفسها الروابط بتملا خطوات التبرع في مكانها من غير إعادة تحميل.

- **فين بتظهر؟** في أي صفحة فيها `<div id="impact-calc"></div>` + `<link rel="stylesheet" href="/css/impact.css">` + `<script defer src="/js/impact.js"></script>` (لو الـCSS مش موجود السكربت بيحمّله). لو العنصر مش موجود السكربت مش بيعمل حاجة. (الـid `impact` مستخدم في سطر الأثر جوه خطوات التبرع، عشان كده الحاسبة `impact-calc`.)
- **البيانات:** `public/data/impact.json`: `title`, `intro`, `default` (المبلغ الافتراضي), `presets` (الأزرار), `min`/`max` (الشريط), `campaigns` (true = ضيف حملات الرئيسية من `content.json` بالوحدة `unit` وسعرها `unitPrice`، ما عدا المكتملة), و`items` بنود ثابتة: `label`, `price`, `unit` (مفرد), `icon` (drop / stethoscope / home / cart / bed / pill / heart / baby / syringe / hospital / star), `text` قالب فيه `{n}` العدد و`{unit}` الوحدة بصيغتها الصحيحة, `link` اختياري.
- **صيغ العدد:** الوحدات المعروفة (جلسة، كشف، شهر، كارت، يوم، سهم، جرعة، كفالة، وجبة، شنطة، جهاز، عملية، أسرة، مريض، طفل، ليلة، علبة، حضانة، متر، ساعة) بتتصرف تلقائياً (جلسة / جلستين / 3 جلسات / 11 جلسة)، وأي وحدة تانية تتكتب `مفرد|مثنى|جمع`. مع 1 و2 الرقم بيتشال من النص لأن الصيغة بتحمله.
- **التعديل من اللوحة:** تبويب **أثر التبرع** (`public/admin/tabs/impact.js` → `PUT /api/console/data/impact`): الإعدادات والبنود (إضافة / ترتيب / حذف) مع معاينة حية تحت كل بند محسوبة على المبلغ الافتراضي.
- **الحركة:** العداد نص بس، الشريط `transform: scaleX`، الكروت بتطلع بالترتيب أول ما تظهر (`transform`/`opacity`) وكله بيتقفل مع "تقليل الحركة". الأرقام بـ `Intl.NumberFormat("ar-EG-u-nu-latn")`.
- الملفات: `public/js/impact.js`, `public/css/impact.css`, `public/data/impact.json`, `public/admin/tabs/impact.js`.

## الأخبار (`/news.html`)

## التطبيق والعمل من غير نت (PWA)
- `public/js/pwa.js` (في كل صفحة بعد `layout.js`، وفي قالب `tools/import_old_site.py`) بيسجّل `public/sw.js` (على https أو localhost بس، ومش جوه `/admin/`)، وبيعرض كارت **«ثبّت تطبيق مرسال»** مرة واحدة (مش في أول صفحة من الزيارة، ولا في التبرع / الزكاة / الفورمات / 404)، ورابط «ثبّت تطبيق مرسال» في الفوتر لما التثبيت يكون متاح، وتنبيه صغير لما النت يقطع أو يرجع. الحالة في `localStorage` → `mersalPwa`. `public/manifest.json` فيه الاسم والأيقونات واختصارات التبرع والزكاة وتواصل معنا.
- قواعد `sw.js`:
  - **الصفحات:** من النت الأول دايماً. النسخة المحفوظة بس لو النت واقع، أو السيرفر رجّع 5xx، أو الصفحة اتأخرت أكتر من 4 ثواني. صفحة مش محفوظة من غير نت ← `offline.html` (الخط الساخن 19340، الصفحات المحفوظة على الجهاز، وآخر نسخة من الحسابات البنكية لو صفحة التبرع اتفتحت قبل كده).
  - **CSS وJS:** من النت دايماً. النسخة المحفوظة **بس** لما الطلب يفشل (من غير نت) أو السيرفر يرجّع 5xx، عمرها ما بتستخدم عشان النت بطيء، فأي نشر جديد بيوصل على طول ومفيش CSS/JS قديم بعد النشر.
  - **`/data/*.json` و`content.json`:** من النت الأول، والنسخة المحفوظة للأوفلاين (أو بعد 6 ثواني لو النت بطيء جداً).
  - **الصور:** النسخة المحفوظة وبتتحدث في الخلفية (60 صورة بالكتير). **الخطوط:** من النسخة المحفوظة.
  - **عمره ما بيلمس** `/api/*` و`/admin*` و`/.auth/*` وأي حاجة اللوحة بتطلبها وأي طلب مش GET (ومتصفح Chrome مش بيشغّل الـworker أصلاً للمسارات دي).
- `staticwebapp.config.json`: `/sw.js` و`/offline.html` بـ `Cache-Control: no-cache` (و`offline.html` noindex).
- لو غيّرت قواعد `sw.js` أو محتوى `offline.html` **غيّر `VERSION` في أول `sw.js`**: النسخة الجديدة بتشتغل فوراً وبتمسح الكاش القديم. النشر العادي مش محتاج كده.
- مفتاح الطوارئ: `SW_ON = false` في `js/pwa.js` + ملف `sw.js` البديل المكتوب في أول `sw.js` (بيشيل الـworker والكاش).
- التثبيت نفسه لازم يتجرّب على موبايل حقيقي (Android Chrome وiPhone Safari).

## الخصوصية والشروط والـSEO
- `privacy.html` (سياسة الخصوصية) و`terms.html` (شروط الاستخدام) مكتوبين على حسب الكود فعلاً: الخانات اللي كل فورم بيجمعها، التخزين في Azure Table بس (مش GitHub)، بيانات البطاقة عند بنك مصر بس، اللي بيتحفظ على جهاز الزائر، ومفيش كوكيز للزوار (كوكي اللوحة بس). **مرسال (ويفضل محامي) لازم يراجعوا الصياغة قبل الإطلاق**، وغيّروا «آخر تحديث» و`dateModified` مع أي تعديل. سطر رقم التسجيل موجود كتعليق HTML في القسم 1 لو حبيتوا تظهروه.
